# 允许回购匹配重复日期

## Goal

调整疑似回购的自动消歧规则：购买日期或开票日期重复时仍可自动配对，同一天内的先后顺序不具有业务意义；缺失日期仍保留冲突。

## Requirements

- 回购组仍要求订单数与发票数相等，并保持现有金额、店铺/销售方、发票子类型和隔离候选图规则。
- 两侧日期必须完整，但不再要求唯一。
- 按自然日期升序配对；同一天内使用记录 ID 升序作为稳定技术排序键，使结果可复现，不赋予业务优先级。
- 每一对仍必须满足购买日期不晚于开票日期；任一配对违反时，整组保留现有晚购冲突。
- 缺失购买日期或开票日期时，整组仍保留疑似回购冲突，原因不再提及重复日期。
- 匹配页、台账状态投影、单笔自动确认和批量自动确认继续复用同一候选计算结果。

## Acceptance Criteria

- [ ] 开票日期重复、购买日期重复或两侧均重复时，数量相等且日期完整的回购组可生成确定、互斥的建议。
- [ ] 同一数据重复计算产生相同的 ID 配对结果。
- [ ] 重复日期建议可通过自动确认重校验和原子批量确认。
- [ ] 缺失日期、数量不一致及购买日期晚于配对发票日期仍产生疑似回购冲突。
- [ ] 相关 Rust 测试、格式检查和 Clippy 通过。

## Technical Approach

- 将 `matching.rs` 中要求日期唯一的排序助手改为要求日期完整的稳定排序助手，排序键为 `(date, id)`。
- 收窄日期冲突文案为仅描述日期缺失。
- 更新回购匹配回归测试、`AGENTS.md` 和后端匹配契约。

## Out of Scope

- 不允许缺失日期参与自动回购配对。
- 不改变普通候选匹配的日期语义。
- 不修改 Tauri API、前端类型、数据库结构或持久化关系。

## Technical Notes

- `src-tauri/src/matching.rs` 当前包含 `ledger-status-project-archive` 任务的未提交改动；实现需在现有内容上追加，提交时只暂存本任务补丁。
- 相关规范：`.trellis/spec/backend/order-invoice-matching-contract.md` 和 `AGENTS.md`。
