# 订单记录与发票匹配

## Goal

新增发票驱动的匹配工作区，自动计算一张发票对应一张或多张订单的候选组合，由用户逐条或批量确认；冲突和异常场景允许人工选择订单组合，并持久化一个订单只能属于一张发票的多对一关系。

## Requirements

### 自动匹配

- 自动分析只生成待确认建议；确认前不持久化、不锁订单。
- 已确认的发票和订单不再参与候选计算，撤销后重新参与。
- 发票必须为 CNY 且 `total_fen` 存在；订单必须有 `paid_amount_fen`。金额缺失记录完全不参与自动或自定义匹配。
- 一对一及多对一都要求订单实付款合计与发票价税合计按整数分严格相等。
- 仅当订单下单日期和发票开票日期都存在且下单日期晚于开票日期时排除；任意一侧日期缺失时跳过日期比较。
- 多订单组合还要求每张订单的店铺名存在，且去除首尾空白、统一全角空格、合并连续空白后完全相同。一对一不要求店铺名。
- 冲突同时包括：同一发票存在多个组合；同一订单出现在不同发票的候选组合中。只有候选唯一且订单没有跨发票竞争时才是可直接确认项。
- 自动组合默认最多 10 张订单、每张发票最多返回 100 个组合；分别允许在设置页配置为 2-20 和 10-500。超过组合数时标记候选过多，转人工处理。
- 页面进入或订单/发票数据变化后重新计算建议。

### 确认与异常处理

- 无冲突建议支持逐条确认；批量确认通过行复选框选择，只允许当前无冲突且规则完整的建议。
- 冲突发票显示多个订单组合，用户通过单选选择一个组合确认。
- 自定义组合复用订单管理表的列、搜索、排序、分页、行详情和复选交互，并支持跨页/搜索保留选择。
- 自定义组合允许金额不等、店铺不同或日期违规，但发票/订单金额必须存在、发票必须为 CNY、订单必须未被占用；前端显示具体差异并要求二次确认。
- 已占用和金额缺失订单在自定义选择器禁用。至少选择一张订单。
- 已确认项可查看并撤销；不直接替换，先撤销再重新匹配。
- 不单独展示或结案无票订单；没有候选的发票保持无法自动匹配，可在数据完整时自定义处理。
- 非 CNY 或金额缺失发票显示不参与原因，不允许自定义组合。

### 编辑与删除联动

- 修改已匹配订单的实付款、下单日期或店铺名，或修改已匹配发票的价税合计、开票日期时，保存前提示会解除匹配；后端在同一事务内解除关系并保存。
- 修改订单号、商品、发票号码、买卖方等非匹配字段不解除关系。
- 已匹配订单或发票禁止删除，后端返回明确错误；用户需先到匹配页撤销。批量删除继续处理其他记录并仅让已匹配项失败。

### 匹配工作区

- 一级导航新增“匹配”。顶部展示状态汇总、筛选、发票搜索、刷新和批量确认。
- 按发票服务端分页，每页默认 50 条；全局候选图和冲突判断不受分页影响。
- 主体为 IDE diff 风格左右对照：左侧发票、右侧订单组合，使用同一垂直滚动容器与成对网格行实现同步滚动和对齐；两侧有粘性表头。
- 点击发票和订单复用现有详情抽屉。
- 页面下方提供冲突/人工处理区；自定义选择固定显示已选订单、合计和差额。
- 已确认项可筛选、查看和撤销。

## Public Interfaces

- 新增 `invoice_matches` 与 `invoice_match_orders` 表。发票关系唯一，订单成员全局唯一；记录来源 `automatic|custom` 和确认时间。
- 新增 `get_matching_page`、`list_matchable_orders`、`confirm_invoice_match`、`confirm_invoice_matches`、`unconfirm_invoice_match` Tauri commands 及 TypeScript 封装。
- 确认命令必须在事务内重新验证记录存在、规则或显式自定义覆盖、订单占用，防止过期页面或重复占用。
- 设置响应和保存请求新增两个匹配限制字段，仍写入版本化 `settings.toml`，保持凭据不出现在公共响应。

## Acceptance Criteria

- [x] 一对一、多对一、日期缺失、店铺规范化、金额/币种缺失、组合限制和全局冲突均按规则返回确定性结果。
- [x] 单条/批量/自定义确认与撤销保持订单唯一占用，过期或竞争请求安全失败。
- [x] 匹配页完成对照浏览、详情打开、复选批量确认、冲突单选和跨页自定义选择。
- [x] 关键字段编辑自动解除；已确认记录删除被拒绝。
- [x] 新 migration 通过 fresh、m0003 upgrade、interrupted recovery、外键和唯一约束测试。
- [x] 设置默认值、合法范围、旧文件补默认值和无凭据响应通过测试。
- [x] Rust 测试、`bun run lint`、`bun run test`、`bun run build` 全部通过。

## Out Of Scope

- 汇率转换或非 CNY 匹配。
- 店铺名与发票销售方名称的映射或比较。
- 无票订单的独立列表和结案状态。
- “订单缺失/无需匹配”发票状态。
- 候选组合持久化或后台导入后自动确认。

## Technical Notes

- SQLite、SeaORM 与 `sea-orm-migration` 继续由 Rust 后端独占。
- 金额使用现有整数分字段；日期比较使用规范化字符串的日期部分。
- 订单复选状态逻辑应抽取可复用部分，但订单管理页仍保持当前页选择语义；只有匹配自定义选择器跨页保留。
