# 订单发票状态与项目归档

## Goal

让用户在订单和发票台账中直接判断匹配及项目归属，支持按状态筛选，并通过项目归档让已完成材料退出日常工作台，同时保留可恢复、可查看和可导出的完整数据。

## Requirements

- 订单和发票列表显示三态匹配状态：`unmatched`（未匹配）、`matched`（存在唯一无冲突自动候选但未确认）、`confirmed`（已持久化确认关系）。
- 两个列表显示项目归属和项目名，支持按匹配状态、已分配/未分配和具体未归档项目筛选；状态以 Badge 和克制的行背景色增强。
- 订单的项目归属通过已确认匹配发票推导；仅有自动候选时不推导项目。
- 发票多选中任一发票已有项目时，禁用整批“分配项目”；删除发票页“移出项目”入口。
- 发票分配弹窗可选择“新建项目”，输入名称后在一个后端事务中创建项目并分配全部发票。
- 项目新增归档时间。项目页使用“进行中/已归档”切换，默认进行中。
- 归档项目仍可查看详情、导出、删除和解除归档，但不可重命名、排序或接收新发票。
- 归档不删除或解除项目成员、匹配关系、订单、发票或文件；关联发票从发票及匹配页隐藏，关联的已确认订单从订单页隐藏，解除归档后恢复。
- 项目名称在归档后继续参与全局唯一约束。
- 复用现有自动匹配候选计算和疑似回购冲突规则，不建立第二套简化匹配规则。

## Acceptance Criteria

- [ ] 台账三态与匹配工作台结果一致，确认关系优先于自动候选。
- [ ] 两页所有筛选在后端分页和计数前生效，组合筛选的总数正确。
- [ ] 行背景不覆盖复选选中态，状态和项目名可直接读取。
- [ ] 已归属发票无法从发票页改派或移出；未归属发票可分配到现有项目或事务性新项目。
- [ ] 归档后关联数据退出订单、发票和匹配工作台，解除归档后恢复；归档项目仍可导出。
- [ ] 后端拒绝针对归档项目的重命名、排序和分配请求。
- [ ] 新数据库、从 m0007 升级及中断迁移恢复测试通过。
- [ ] 前端 lint、type-check/build、组件测试和相关 Rust 测试通过。

## Technical Approach

- 添加可重复执行的 `m0008_project_archival` migration，为 `projects` 增加 nullable `archived_at` 并更新 SeaORM entity。
- 抽取匹配工作区内部的台账状态计算结果，供匹配页、订单列表和发票列表复用；订单状态由唯一候选中的订单及已确认订单映射。
- 扩展 Tauri query/response types 和 TypeScript API types；状态与归档过滤均由 Rust 查询层负责。
- 新增 archive/unarchive 和 create-and-assign Tauri commands；后者使用单个 SQLite transaction。
- 更新 React 表格、筛选工具栏、项目分段视图、分配弹窗和刷新 token 协作。

## Decision (ADR-lite)

**Context**: 匹配工作台已有五态实时计算，而台账需要更简洁且可跨订单/发票统一的口径；归档需要隐藏日常工作但不能破坏审计和导出数据。

**Decision**: 台账使用未匹配/已匹配/已确认三态，其中只有唯一无冲突建议为已匹配；归档作为项目生命周期字段，仅影响日常工作台可见性和成员变更权限。

**Consequences**: 列表查询需要共享候选计算并在内存状态筛选后分页，避免口径漂移；归档项目仍占用名称并保存所有关系。

## Out of Scope

- 不新增独立的归档订单或归档发票页面。
- 不允许从发票页改派已有项目发票。
- 不将项目可导出、待确认或异常健康度作为台账项目状态筛选。
