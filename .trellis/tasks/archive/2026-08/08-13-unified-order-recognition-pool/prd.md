# 统一订单识别池与多协议识别

## Goal

移除订单导入的用户可见批次概念，将所有订单截图放入一个持久化任务池，并支持 Ollama 实时识别、通用 OpenAI Chat Completions 兼容实时识别和阿里云百炼 OpenAI 兼容文件 Batch 异步识别。

## Requirements

- 仅移除订单导入批次；发票导入批次和腾讯云 OCR 工作流保持不变。
- 订单任务页的订单 Tab 分为左右两栏：左侧为待处理、处理中、批次锁定和失败待重试的任务池；右侧为成功识别后的不可变完成日志。
- 实时提供方自动消费统一任务池，使用全局并发上限；识别期间允许继续导入，新任务动态入队。
- 实时失败任务返回左栏并等待人工重试，不能自动无限重试。
- 百炼模式由用户手动提交当前全部 pending 任务。任务冻结后标注本地递增短编号 `B000001`；多个远端批次可以同时运行，新导入任务继续留在池中并可提交为下一批次。
- 百炼使用 OpenAI 兼容文件 Batch：生成 JSONL、上传文件、创建 Batch、轮询、下载成功和错误 JSONL，并通过 `custom_id` 对应本地任务。
- 支持取消整个百炼批次。取消后先导入已完成结果，再把未完成任务解锁为失败待重试。
- 左侧未锁定的 pending/failed 任务可物理删除；同时删除受管图片并释放哈希。processing 和批次锁定任务不能单独删除。
- 识别成功必须原子创建订单、把图片所有权转给订单、创建不可变完成日志并移除池任务。
- 完成日志与订单图片解耦。订单编辑或删除不得改变完成日志；删除订单仍清理订单图片并释放哈希。
- 设置文件升级为提供方感知的版本，安全保存可选 OpenAI API Key 和必需的百炼 API Key；公共响应不得返回明文凭据。
- 切换到实时提供方后，所有 pending 项按当前设置自动消费；切换到百炼后停止启动新的实时任务，已经在途的实时任务允许完成。已提交批次使用提交时的配置快照。
- 订单任务更新使用独立事件驱动池、日志和订单列表刷新；不复用发票事件。

## Data Migration

- 旧成功订单任务转换为完成日志，既有订单接管原图片元数据和路径。
- 旧 failed/interrupted/queued/processing 任务进入统一池；应用退出时未完成的任务标为失败并等待人工重试。
- 旧 skipped/canceled 记录不生成完成日志；旧订单批次不再通过公共 API 或界面展示。
- SQLite 迁移 DDL 必须可安全重试，并覆盖全新数据库、旧版本升级和中断迁移恢复。

## Interfaces

- 池级命令替换订单批次命令：导入图片、读取池、分页读取完成日志、单条/全部重试、删除任务、提交百炼批次、取消百炼批次。
- `check_ollama` 泛化为按当前配置检查订单识别提供方。
- 前后端移除订单侧 `BatchDetail`、`ImportBatchSummary`、`latestBatch` 和批次选择状态；所有 `InvoiceBatch*` 接口保持不变。

## Acceptance Criteria

- 不同导入动作的实时任务严格共享一个动态并发池，运行期间新增任务可被消费。
- 百炼批次可以并行运行，重启后恢复轮询，不重复上传、不重复生成订单。
- 百炼部分成功、错误文件、取消、结果缺失和重复结果都能幂等对账。
- 右侧完成日志创建后不可变，订单删除不会删除或修改日志。
- 删除未锁定池任务会删除图片并允许同图重新导入。
- 旧数据库升级后订单详情图片可用，旧未完成项可重试，旧批次 UI 消失。
- Rust format/clippy/tests、frontend lint/typecheck/tests 全部通过。

## Assumptions

- 百炼默认北京地域 OpenAI 兼容地址、24h completion window，并默认关闭思考模式；允许配置完整 base URL 和显式开启思考。
- 单次百炼提交使用当前全部 pending 项，不提供部分勾选。
- 百炼提交前执行 50,000 项、500 MB、单行 6 MB 限制检查；不合格任务标为失败，合格任务仍可提交。
- 重复图片直接跳过并向导入调用方报告，不进入池或完成日志。
