# 摘要生成管理与可视化

## Goal

把已确认匹配的商品摘要扩展为可配置、可操作、可审计的工作流，在任务中心、设置、匹配和项目页面直观展示状态，同时保持摘要失败不阻塞匹配与导出。

## Requirements

- 摘要状态增加 `not_generated`，设置增加 `automatic | manual` 方式和独立 `1..=8` 并发数；旧设置默认自动、并发 1。
- 自动模式下新匹配和失效摘要进入 `pending`；手动模式下进入 `not_generated`。切到手动时暂停未领取任务，切回自动时排队全部未生成任务。
- 任务中心新增摘要页签，提供当前记录与最近 180 天尝试历史、搜索/状态筛选/分页、单条生成或重试、批量生成和人工编辑。
- 每次模型尝试保存不可变日志及结构化输入快照、触发方式、模型、时间、结果或错误；人工编辑也写成功日志。删除发票级联删除日志，撤销匹配保留日志。
- 人工摘要来源为 `manual`，输入变化或自动模式不得覆盖；只有用户明确生成且生成成功后才替换。人工摘要生成失败时继续作为当前显示名。
- 项目列表和详情返回后端聚合的摘要总状态及各状态计数，归档项目一致；摘要状态不参与导出阻塞。
- 匹配查询增加摘要状态筛选和全局摘要计数。选择具体摘要状态时前端自动切到已确认，筛选在服务端全局投影后、分页前执行。
- 启动时把遗留运行尝试记为中断，并恢复对应工作；并发完成必须继续使用状态和输入哈希防止陈旧响应覆盖。
- 更新 `AGENTS.md` 及相关 Trellis 前后端契约。

## Acceptance Criteria

- [ ] 手动模式不会自动处理未生成摘要，支持单条和批量排队；自动模式会处理所有未生成摘要。
- [ ] 设置切换与并发修改无需重启即可影响后续队列领取。
- [ ] 摘要任务页能查看当前状态、人工编辑及每次尝试的结构化输入与结果。
- [ ] 人工摘要在输入变化后保持不变，明确重新生成失败也不会丢失人工显示名。
- [ ] 匹配摘要筛选与匹配状态联动正确，统计不依赖当前页。
- [ ] 项目列表和详情显示项目级状态及计数，摘要失败不影响已有导出资格。
- [ ] 迁移覆盖新建、上一版本升级和中断恢复；日志按 180 天清理。
- [ ] Rust 测试、Clippy、前端 lint/test/build 全部通过。

## Technical Approach

- 新增可重复的 SeaORM 迁移，扩展 `invoice_matches` 状态/来源并建立尝试日志表及查询索引。
- `SettingsStore` 升级版本并让摘要队列动态读取方式和并发；用可调整的并发 drain 保留持久状态和事件失效语义。
- 把摘要当前记录、尝试日志、人工编辑、单条/批量排队封装为 `Database` 操作和类型化 Tauri 命令。
- 后端统一计算匹配筛选统计与项目摘要聚合，React 只渲染类型化投影。

## Out of Scope

- 原始模型响应全文、日志导出、调用成本/耗时图表、自定义日志保留期。
- 摘要状态阻塞项目导出或改变匹配确认关系。
- 自动重试失败任务。

## Technical Notes

- 遵循 `.trellis/spec/backend/database-guidelines.md`、匹配/项目契约及对应前端契约。
- 当前摘要使用 `invoice_matches` 的状态、输入哈希和 `match-summary-updated` 失效事件；扩展这些路径而不建立第二套状态源。
